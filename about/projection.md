# Tech
1. Go deeper + system design
2. Build one complete architecture project
3. Learn Rust as a secondary skill

With four years of Go, switching immediately to Rust may dilute your existing advantage. Your strongest profile would be:
Go backend engineer who can design reliable distributed systems, with Rust capability for performance- or safety-critical components.

## Recommended allocation
- 50%: advanced Go and production engineering
- 35%: system design and architecture
- 15%: Rust

Go deep into concurrency, networking, profiling, memory behavior, database performance, observability, testing, and API/module design. The official Go documentation specifically covers diagnostics, race detection, profiling, PGO, modules, and concurrency.

Learn Rust enough to understand ownership, borrowing, async, concurrency, and performance. Rust becomes especially valuable if you target infrastructure, storage engines, networking, embedded systems, WebAssembly, or high-performance services. 

## Best portfolio project
Design and partially implement a serious system, for example:
A multi-tenant event-processing platform in Go

Constraints:
- 10,000 events per second
- At-least-once processing
- Per-tenant rate limits
- Retry with exponential backoff
- Idempotency
- Worker crashes and recovery
- p99 API latency below 200 ms
- 99.9% availability
- Auditing and observability
- Defined monthly infrastructure budget

Produce:
- Requirements and assumptions
- Capacity estimates
- API design
- Data model
- Component diagram
- Queue and storage choices
- Failure-mode analysis
- Security model
- Deployment architecture
- Monitoring and alerting
- Scaling plan
- Migration plan
- Cost/trade-off analysis
- A few Architecture Decision Records

ADRs are useful because they document the context, decision, alternatives, and consequences of architectural choices. 
Then implement the most difficult vertical slice in Go. Later, replace one carefully selected component—such as a parser, high-throughput worker, or performance-sensitive library—with Rust. That gives you evidence of judgment rather than merely listing two languages.

# Domain
A good structure would be:
- Core specialty: data, product, finance, risk, operations, technology, or consulting
- Adjacent skill 1: communication, sales, or stakeholder management
- Adjacent skill 2: business, strategy, or financial knowledge

Examples:
- Finance + data
- Technology + product management
- Operations + risk/compliance
- Marketing + analytics
- Technical expertise + consulting

Strongest possibilities:
1. Technology and digital business

3. Consulting and professional services
   Strategy, research, management consulting, recruitment, advisory, client solutions, or business development.
4. Education, training, content, and communication
